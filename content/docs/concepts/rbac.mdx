---
title: Authority roles
description: Manage Protocol v1 authorities and delegate scoped spending through sessions.
---

Roles control administrative permissions. Configure spending limits on
[session keys](/concepts/session-keys).

| Operation | Owner | Admin | Spender |
| --- | --- | --- | --- |
| Execute | Yes | Yes | Yes |
| Create or revoke a session | Yes | Yes | No |
| Add authority | Owner, Admin or Spender | Spender only | No |
| Remove authority | Admin or Spender | Spender only | No |
| Transfer ownership | Yes | No | No |
| Authorize a deferred action | Passkey only | Passkey only | No |

The published SDK exports `ROLE_OWNER` (0), `ROLE_ADMIN` (1) and `ROLE_SPENDER` (2).
A Spender can execute without a session spending cap. Use a session for integrations
that need a defined allowance or expiry. Use `transferOwnership` to replace an Owner.

A valid deferred payload can be submitted by a transaction payer. Its authorization
record controls expiry and the original funding payer's refund.
