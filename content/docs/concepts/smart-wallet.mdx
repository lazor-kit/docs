---
title: Smart wallet
description: Understand the Protocol v1 wallet, vault, authority and session PDAs.
---

A LazorKit Protocol wallet has an identity PDA and a separate vault PDA. **Use the
vault PDA to receive SOL and tokens.** Use the wallet PDA when building program calls.

| Account | Seeds | Purpose |
| --- | --- | --- |
| Wallet | `["wallet", user_seed]` | Wallet identity and ownership state |
| Vault | `["vault", wallet]` | Holds assets spent by the program |
| Authority | `["authority", wallet, id_hash]` | Per-key authority and passkey counter |
| Session | `["session", wallet, session_key]` | Short-lived signer and optional actions |
| Deferred | `["deferred", wallet, authority, counter]` | Pending authorization, expiry and funding payer |

Use the exact program ID for your cluster. For a passkey, the authority identifier
is the SHA-256 hash of the credential ID bytes. For an Ed25519 authority, it is the key's
32 public bytes. A passkey proves a transaction challenge through the Secp256r1
precompile. Prepare a fresh challenge for each operation.

To reconnect a returning wallet, start from the wallet PDA your app established
during onboarding. Revalidate its owner and authority on the selected cluster.
A credential lookup can return more than one wallet candidate.

See [Networks](/networks), [authority roles](/concepts/rbac) and [session keys](/concepts/session-keys).
