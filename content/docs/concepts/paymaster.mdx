---
title: Paymaster
description: Sponsor Protocol v1 transactions with a compatible fee payer.
---

A paymaster pays the transaction's SOL fees and submits the transaction. The signed
transaction must use that paymaster as its fee payer. Where Protocol fees are enabled,
the SDK resolves the fee accounts from the deployment's on-chain configuration.
Check the network, program ID and fee configuration before using a paymaster.

## Payment and reimbursement

A wallet may have tokens and no SOL if the paymaster covers network fees. Reimbursing
the payer in a token is an application or relayer policy. Show the mint, amount and
recipient to the user before approval. Account creation can require rent even when
the paymaster covers the network fee. Confirm that the selected flow provides a
funding signer and that the relay accepts the transaction format.

## Retry and confirmation

Record the signature when the paymaster returns it and wait for confirmation with
the configured RPC. When the result is uncertain, check the signature before
preparing a new payment. A fresh passkey approval uses fresh transaction context.
