## Wallet state

### `WalletInfo`

The persisted record written to `AsyncStorage` after `connect`.

```ts
interface WalletInfo {
  credentialId: string;         // WebAuthn credential ID (base64)
  passkeyPubkey: number[];      // 33-byte compressed secp256r1 pubkey
  expo: string;
  platform: string;             // 'ios' | 'android' | …

  /** Vault PDA (base58) — the address funds live at. Show this to users. */
  smartWallet: string;

  /** Wallet metadata PDA (base58). Needed for raw LazorKitClient calls. */
  walletPda: string;

  /** Authority PDA (base58) tied to this passkey credential. */
  walletDevice: string;

  /** 1 = made before LazorKit v2, 2 = since. Absent on records saved before 2.0.0 (= v1). */
  protocolVersion?: 1 | 2;
}
```

<Callout type="info">
  On mobile, `smartWallet` is the **vault PDA** (since the April 2026 store format; older
  persisted records are migrated on load). On the web SDK the same field is the wallet
  PDA — see [Networks & versions](/networks#which-address-is-the-users-wallet).
</Callout>

### `WalletConfig` / `LazorKitProviderProps`

```ts
interface WalletConfig {
  portalUrl: string;
  configPaymaster: { paymasterUrl: string; apiKey?: string };   // v2 wallets
  v1ConfigPaymaster?: { paymasterUrl: string; apiKey?: string }; // v1 wallets (2.0.0+)
  rpcUrl?: string;
  cluster?: 'mainnet' | 'devnet';                                // when rpcUrl does not say (2.0.0+)
  rpId?: string;
}

interface LazorKitProviderProps {
  rpcUrl?: string;
  portalUrl?: string;
  configPaymaster?: { paymasterUrl: string; apiKey?: string };
  v1ConfigPaymaster?: { paymasterUrl: string; apiKey?: string };
  cluster?: 'mainnet' | 'devnet';
  rpId?: string;
  isDebug?: boolean;
  children: ReactNode;
}
```

## Wallet confirmation

<Callout type="warn" title="Version note">
  Everything in this section is in `@lazorkit/wallet-mobile-adapter` **2.0.0 and later**.
  Earlier versions — `1.x`, and the `2.0.0` betas up to `2.0.0-beta.4` — do not have it.
  How it is used: [Wallet Confirmation](/react-native-sdk/wallet-confirmation).
</Callout>

### Provider and `connect` options

```ts
interface LazorKitProviderProps {
  // ...the props above, plus:
  onConfirmWallet?: OnConfirmWallet;      // default 'builtin'
  trustedAuthorities?: readonly string[]; // your own Ed25519 keys, base58
  watchMints?: readonly string[];         // SPL Token mints your app receives, base58
}

interface ConnectOptions {
  redirectUrl: string;
  confirmWallet?: string;                 // vault (or wallet PDA) the user chose
  onConfirmWallet?: OnConfirmWallet;      // overrides the provider's for this call
  onSuccess?: (wallet: WalletInfo) => void;
  onFail?: (error: Error) => void;
}
```

### `WalletChoice`

A wallet the passkey is proven to hold a key of, that `connect` will not adopt without the
user. Show the vault address; the order is not a recommendation.

```ts
interface WalletChoice {
  wallet: string;                         // wallet PDA
  vault: string;                          // vault PDA — where the funds are. Show this one.
  version: 1 | 2;                         // 1 = made before LazorKit v2, not migrated yet
  lamports: number;                       // vault balance
  signatureCount: number;                 // 0 = not used with this passkey yet
  vaultIsSystemAccount: boolean;          // false: vault handed to another program
  otherAuthorities: {                     // every authority except this passkey's
    address: string;                      // the authority account
    type: 'passkey' | 'key';              // passkey = secp256r1, key = Ed25519
    role: 'owner' | 'admin' | 'spender' | 'unknown'; // 'spender' = Delegate
    key?: string;                         // 'key' only: the Ed25519 key
    sameRelyingParty?: boolean;           // 'passkey' only: same relying party
    trusted: boolean;                     // in trustedAuthorities; a passkey never is
  }[];
  liveSessions: {                         // sessions that can still sign
    address: string;
    sessionKey: string | null;            // null when unreadable
    approxExpiresAt: number | null;       // ms since the epoch (slots × 400 ms)
    trusted: boolean;
  }[];
  pendingDeferred: {                      // authorized, not yet run or expired. Never trusted.
    address: string;
    approxExpiresAt: number | null;
  }[];
  tokenGrants: {                          // rights over the vault's token accounts
    tokenAccount: string;
    tokenProgram: string;
    mint: string | null;
    kind: 'delegate' | 'closeAuthority' | 'owner' | 'unreadable';
    grantee: string | null;
    trusted: boolean;
  }[];
}
```

### `ConfirmWalletRequest`

```ts
interface ConfirmWalletRequest {
  credentialId: string;
  candidates: WalletChoice[];
}
```

### `ConfirmWalletHandler`

Your own chooser. Resolve with the chosen candidate's `vault` (or `wallet`), or `null` when
the user recognises none of them. Never choose for the user.

```ts
type ConfirmWalletHandler = (
  request: ConfirmWalletRequest,
) => Promise<{ wallet: string } | null> | { wallet: string } | null;
```

### `OnConfirmWallet`

```ts
type OnConfirmWallet = ConfirmWalletHandler | 'builtin' | 'throw';
```

### `<WalletChooser />`

The built-in chooser, for rendering inside your own `<Modal>` on iOS — while it is mounted
it draws instead of the provider's. See
[Wallet Confirmation › iOS](/react-native-sdk/wallet-confirmation#ios-shows-one-modal-at-a-time).

### Errors

```ts
class WalletNeedsConfirmationError extends Error {      // onConfirmWallet: 'throw'
```

## Options & payloads

### `SignOptions`

Trailing argument on every passkey-signed method (opens the portal).

```ts
interface SignOptions {
  redirectUrl: string;                    // your app deep-link scheme
  onSuccess?: (result: any) => void;
  onFail?: (error: Error) => void;
}
```

### `DisconnectOptions`

`disconnect`'s argument, on the hook and on the store (2.3.0+).

```ts
interface DisconnectOptions {
  onSuccess?: () => void;
  onFail?: (error: Error) => void;
}
```

### `TxCallbacks`

Trailing argument on **non-passkey** flows — session-signed txs, `executeDeferred`,
`reclaimDeferred`. No `redirectUrl` needed.

```ts
interface TxCallbacks {
  onSuccess?: (signature: string) => void;
  onFail?: (error: Error) => void;
}
```

### Transaction payloads

```ts
interface TransactionOptions {
  feeToken?: string;                                       // SPL mint base58
  addressLookupTableAccounts?: AddressLookupTableAccount[];
  computeUnitLimit?: number;
  clusterSimulation?: 'devnet' | 'mainnet';
}

interface SignAndSendTransactionPayload {
  instructions: TransactionInstruction[];
  transactionOptions?: TransactionOptions;
}

interface AuthorizeExecutePayload extends SignAndSendTransactionPayload {
  expiryOffset?: number;                  // slots after TX1, 10–9000; default 1500
}

// For `authorizeDeferred` — TX1 only, returns payload for later TX2.
interface AuthorizePayload {
  instructions: TransactionInstruction[];
  expiryOffset?: number;                  // slots after TX1, 10–9000; default 1500
  transactionOptions?: TransactionOptions;
}

// Returned from `authorizeDeferred`.
interface AuthorizeResult {
  signature: string;                      // TX1 signature
  deferredPayload: DeferredPayload;       // feed to executeDeferred later
  deferredExecPda: PublicKey;
  counter: number;
}

// For `executeDeferred` — TX2 only.
interface ExecuteDeferredPayload {
  deferredPayload: DeferredPayload;
  refundDestination?: PublicKey;          // leave unset: the program accepts only the Authorize payer
  transactionOptions?: TransactionOptions;
}

// For `reclaimDeferred` — cleanup path, after the window.
interface ReclaimDeferredPayload {
  deferredExecPda: PublicKey;
  refundDestination?: PublicKey;          // leave unset: the program accepts only the Authorize payer
}

interface SessionSignPayload {
  sessionKeypair: Keypair;                // Ed25519 keypair from createSession
  sessionPda: PublicKey;
  instructions: TransactionInstruction[];
  transactionOptions?: TransactionOptions;
}

// Internal shape produced by authorize*/used by executeDeferred. Re-exported from
// the SDK so you can persist it across sessions / machines via the wire helpers.
// Serialized, it carries `version: 2` and is refused across the v1/v2 boundary.
interface DeferredPayload {
  walletPda: PublicKey;
  deferredExecPda: PublicKey;
  compactInstructions: {
    programIdIndex: number;
    accountIndexes: number[];
    data: Uint8Array;
  }[];
  remainingAccounts: {
    pubkey: PublicKey;
    isSigner: boolean;
    isWritable: boolean;
  }[];
  executor?: PublicKey;                   // who the accounts hash expects to send TX2
  refundDestination?: PublicKey;          // the Authorize payer
}

// Wire helpers (JSON-safe strings) for cross-machine deferred flows.
serializeDeferredPayload(p: DeferredPayload): string;
deserializeDeferredPayload(s: string): DeferredPayload;

interface TransferSolPayload {
  recipient: PublicKey;
  lamports: bigint | number;
  transactionOptions?: TransactionOptions;
}
```

### Session payloads

```ts
interface CreateSessionPayload {
  sessionKey: PublicKey;                  // fresh Ed25519 public key; you keep the secret key
  expiresAtSlot: bigint;                  // absolute slot, at most 6,480,000 slots ahead
  actions?: SessionAction[];              // required unless unrestricted
  unrestricted?: boolean;                 // a session with no limits, explicitly (2.0.0+)
}

interface RevokeSessionPayload {
  sessionPda: PublicKey;
  refundDestination?: PublicKey;          // default: paymaster fee payer
}
```

### Authority payloads

```ts
interface AddAuthorityPayload {
  newEd25519Pubkey: PublicKey;
  role: number;                           // required, no default: ROLE_SPENDER (2, a Delegate) | ROLE_ADMIN (1) | ROLE_OWNER (0, v1 only)
  policy?: Uint8Array;                    // required for ROLE_SPENDER on v2: serializeActions([...])
  unrestricted?: boolean;                 // required to add a key to a v1 wallet
}

interface RemoveAuthorityPayload {
  targetAuthorityPda: PublicKey;
  refundDestination?: PublicKey;
}

interface AuthorityEntry {
  authorityPda: PublicKey;
  authorityType: number;                  // 0 = ed25519, 1 = secp256r1
  role: number;                           // 0 = Owner, 1 = Admin, 2 = Delegate
  credential: Uint8Array;                 // 32 bytes
  secp256r1Pubkey?: Uint8Array;           // 33 bytes, secp256r1 only
}

type ListAuthoritiesResult = AuthorityEntry[];
```

<Callout type="info" title="Changed in 2.3.0">
  Breaking: `AddAuthorityPayload.role` is required. In 2.2.1 it was optional and defaulted
  to `ROLE_SPENDER`. See
  [useWallet › addAuthorityEd25519](/react-native-sdk/use-wallet#addauthorityed25519).
</Callout>

## Session actions

Actions are **immutable policies** attached to a session at creation — or, serialized with
`serializeActions`, to a Delegate authority. The on-chain program enforces them on every
`Execute` signed by that key.

### Builder — `Actions`

Prefer these helpers over hand-building the raw object:

```ts
import { Actions } from '@lazorkit/wallet-mobile-adapter';

// SOL
Actions.solLimit(remainingLamports, expiresAt?)
Actions.solRecurringLimit({ limit, window, expiresAt? })
Actions.solMaxPerTx(maxLamports, expiresAt?)

// SPL tokens
Actions.tokenLimit({ mint, remaining, expiresAt? })
Actions.tokenRecurringLimit({ mint, limit, window, expiresAt? })
Actions.tokenMaxPerTx({ mint, max, expiresAt? })

// CPI filters
Actions.programWhitelist(programId, expiresAt?)
Actions.programBlacklist(programId, expiresAt?)
```

### Raw enum / union

```ts
enum SessionActionType {
  SolLimit            = 1,
  SolRecurringLimit   = 2,
  SolMaxPerTx         = 3,
  TokenLimit          = 4,
  TokenRecurringLimit = 5,
  TokenMaxPerTx       = 6,
  ProgramWhitelist    = 10,
  ProgramBlacklist    = 11,
}

type SessionAction =
  | { type: SessionActionType.SolLimit; remaining: bigint; expiresAt?: bigint }
  | { type: SessionActionType.SolRecurringLimit; limit: bigint; window: bigint; expiresAt?: bigint }
  | { type: SessionActionType.SolMaxPerTx; max: bigint; expiresAt?: bigint }
  | { type: SessionActionType.TokenLimit; mint: PublicKey; remaining: bigint; expiresAt?: bigint }
  | { type: SessionActionType.TokenRecurringLimit; mint: PublicKey; limit: bigint; window: bigint; expiresAt?: bigint }
  | { type: SessionActionType.TokenMaxPerTx; mint: PublicKey; max: bigint; expiresAt?: bigint }
  | { type: SessionActionType.ProgramWhitelist; programId: PublicKey; expiresAt?: bigint }
  | { type: SessionActionType.ProgramBlacklist; programId: PublicKey; expiresAt?: bigint };
```

### Common limits (cheat sheet)

| Slot window   | at 400 ms a slot |
| ------------- | ---------------- |
| `9_000n`      | 1 hour           |
| `54_000n`     | 6 hours          |
| `216_000n`    | 1 day            |
| `1_512_000n`  | 7 days           |

A slot's length varies by cluster and load (devnet ran near 230 ms in September 2026), so
these are approximations.

## Errors

All exported as classes. When each is thrown and what to do: [Errors](/errors).

```ts
class LazorKitError extends Error { code?: string }
class WalletConnectionError extends LazorKitError {}   // "Already connecting", bad redirect
class SigningError          extends LazorKitError {}   // another sign action is running; no wallet
class PortalCancelledError  extends LazorKitError {}   // the portal was closed
class WalletChooserNotShownError extends LazorKitError {} // iOS: chooser under another modal

// Sending (2.1.0+)
class TransactionFailedError extends Error {           // landed and failed
  readonly signature: string;
  readonly transactionError: TransactionError;
  readonly slot: number;
  readonly logs?: string[];
}
class TransactionExpiredError extends Error { readonly signature: string }
class TransactionOutcomeUnknownError extends Error { readonly signature: string | undefined }
class ConfirmationTimeoutError extends TransactionOutcomeUnknownError { readonly waitedMs: number }
class PreviousTransactionPendingError extends Error { readonly pendingSignature: string | undefined }
class SignatureReusedError extends Error { readonly code: 3006 }
class PaymasterError extends Error {
  readonly code?: number; readonly data?: unknown; readonly httpStatus?: number;
  readonly signature?: string; maybeSent: boolean;
}

// Deferred execution (2.2.0+)
class DeferredExpiredError extends Error {
  readonly code: 3014;
  readonly deferredExecPda: PublicKey;             // holds the rent: pass it to reclaimDeferred
  readonly authorizeSignature: string | undefined; // TX1, when the same call sent it
  readonly expiresAtSlot: bigint | undefined;
}
interface DeferredFailureContext { deferredExecPda?: PublicKey; authorizeSignature?: string; expiresAtSlot?: bigint } // 2.2.1+

// v1 wallets (2.0.0+)
class V1WalletRetiredError extends Error { readonly code: 4018 }
class V1WalletMigratedError extends Error {}

// Re-exported from @lazorkit/sdk-legacy
class MinContextSlotNotReachedError extends Error {}
```

Also exported: `isDeferredExpiredError`, `isSignatureReusedError` and
`isRetiredDeploymentError`, each true for its class from any copy of the package, also
wrapped in `cause` or a wallet-adapter `WalletError` (since 2.3.0; in 2.2.1 the last two
read only the error's text and missed the adapter's own errors), `SIGNATURE_REUSED_CODE`, `DEFERRED_EXPIRED_CODE`,
`RETIRED_DEPLOYMENT_CODE`, `MIN_DEFERRED_EXPIRY_SLOTS` (10) and
`MAX_DEFERRED_EXPIRY_SLOTS` (9000).

On-chain program errors appear inside error messages and logs as hex codes —
`0xbd0`, `0xbd1`, etc. See [Errors › Program error codes](/errors#program-error-codes).
