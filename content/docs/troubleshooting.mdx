---
title: Protocol troubleshooting
description: Troubleshoot Protocol v1 wallets, passkeys and transactions.
---

## Wallet address or balance

Display the **vault PDA** as the receive address. Keep the **wallet PDA** for program
calls. If the balance is unexpected, confirm the program ID, cluster, vault and token
mint. Existing Protocol v1 wallets retain their addresses through compatible upgrades.

## Passkey or signing failure

Open the portal on the relying-party domain the credential was created for. Use its
registered app origin or redirect. If a passkey request is stale or already used, build
the intended instructions again and request a fresh approval. An invalid message hash
can indicate a mismatch between the client's instruction builder and the deployed binary.

## Session limits

Use the session registered to the selected wallet, with its matching Ed25519 key.
Expiry is an absolute slot. Check the session's actions and their token mint, units,
remaining balance and recurring window. A wallet Owner or Admin can revoke the
session and select its rent refund account.

## Deferred execution

Reuse the payload returned by `finalizeAuthorize`. Check its expiry before submitting
`executeDeferredFromPayload`. On expiry the original payer can reclaim the record.
If a large action cannot fit the selected transaction format, check the serialized
size and the relayer's supported transaction versions before prompting for approval.

## Network or relay

Use the program ID and a paymaster that supports the same cluster. Inspect the relay
response and the on-chain status of any signature it returned. When an attempt's
outcome is uncertain, check the original signature before asking for another payment.

See [Networks](/networks) and [Protocol errors](/errors).
