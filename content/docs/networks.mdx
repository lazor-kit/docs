LazorKit has two protocol versions on chain, each at its own program id. Every SDK
release speaks one or both of them. This page is the one place that says what is
deployed where; the rest of the docs link here instead of repeating it. Build hashes,
upgrade authorities, audit status, retired programs and tested SDK combinations are on
[Versions & compatibility](/versions).

<Callout type="warn" title="Status on 2026-10-11">
  - **Mainnet runs protocol v1** (`LazorjRF…`). The v2 mainnet program
    (`LazorFroi…`) is **not deployed yet**: its account does not exist on chain.
  - **Devnet runs both.** v2 (`57bTNW…`) is deployed. Its `ProtocolConfig` is not
    initialised, so no protocol fee is charged there.
  - **Devnet's v2 measures session time in Unix seconds** since 2026-10-11 (slot
    509,609,649): a session's expiry, an action's expiry and a recurring window are read
    against the cluster clock, not the slot. `@lazorkit/wallet` 3.4.1 and
    `@lazorkit/wallet-mobile-adapter` 2.4.0 (`latest`) still send slots, so their
    `createSession` is refused there with 3008; use 4.0 / 3.0 (`next`). Sessions created
    before the upgrade have expired. See [Migrating to 4.0](/react-sdk/migrating-to-4).
  - **On devnet, a policy bounds every asset** (errors 3037 and 3038, since 2026-10-03): a
    session's or a Delegate's policy names what may leave the wallet, and nothing else may.
    And only an Owner may change who controls the vault or its token accounts (3030–3032).
    See [Session Keys › What a policy bounds](/concepts/session-keys#what-a-policy-bounds).
  - v1 will be retired to a **sunset binary** after v2 is live on mainnet. From then
    on a v1 wallet can only move its funds to v2. See
    [Migrating from v1](/v1-to-v2).
</Callout>

## Program ids

| Cluster | Protocol | Program id | Constant | On chain (2026-10-11) |
| ------- | -------- | ---------- | -------- | --------------------- |
| mainnet | v2 | `LazorFroiVuAjcwwQ2me83vTr5nc5NRxSaTg3pmEXC8` | `PROGRAM_ID_MAINNET` | **not deployed** |
| mainnet | v1 | `LazorjRFNavitUaBu5m3WaNPjU1maipvSW2rZfAFAKi` | `PROGRAM_ID_MAINNET_V1` | deployed (full v1) |
| devnet | v2 | `57bTNWqtYTJbWuLWASKo6GqUTAK6oFDUR5c6hEc6V8nv` | `PROGRAM_ID_DEVNET` | deployed, no protocol fee configured; session time in Unix seconds (build `f2779b66…`) |
| devnet | v1 | `4h3XoNReAgEcHVxcZ8sw2aufi9MTr7BbvYYjzjWDyDxS` | `PROGRAM_ID_DEVNET_V1` | deployed |

The constants are exported by `@lazorkit/sdk-legacy` 1.2.0 and later, by
`@lazorkit/sdk`, and re-exported by `@lazorkit/wallet` and
`@lazorkit/wallet-mobile-adapter`. `PROGRAM_ID` in the wallet packages is the **v2
mainnet** id.

```ts
import {
  PROGRAM_ID_MAINNET,
  PROGRAM_ID_MAINNET_V1,
  PROGRAM_ID_DEVNET,
  PROGRAM_ID_DEVNET_V1,
} from '@lazorkit/sdk-legacy';

console.log(PROGRAM_ID_DEVNET.toBase58()); // 57bTNWqtYTJbWuLWASKo6GqUTAK6oFDUR5c6hEc6V8nv
```

Each binary embeds its own id and refuses to run anywhere else (`WrongProgramAddress`,
4017). A v2 address never collides with a v1 one: v2 PDA seeds are prefixed `lk2:`
and its account discriminators are `0x21`–`0x27`.

## Packages

| Package | Version | npm tag | Protocol | Notes |
| ------- | ------- | ------- | -------- | ----- |
| `@lazorkit/wallet` (React) | 3.4.1 | `latest` | v2, and v1 for existing v1 wallets | Routes each action by the wallet's protocol. Creates new wallets on v2 only. Sends session expiry as a slot: cannot create a session on devnet's v2 (3008). |
| `@lazorkit/wallet` (React) | 4.0.0-next.0 | `next` | the same | Pre-release. Embedded mode, typed approval requests, session time in seconds. `npm install @lazorkit/wallet@next`; see [Migrating to 4.0](/react-sdk/migrating-to-4). |
| `@lazorkit/wallet-mobile-adapter` (React Native) | 2.4.0 | `latest` | v2, and v1 for existing v1 wallets | Same routing, and the same devnet limit on sessions. The `beta` tag still points at the old `2.0.0-beta.4`: do not install `@beta`. |
| `@lazorkit/wallet-mobile-adapter` (React Native) | 3.0.0-next.0 | `next` | the same | Pre-release. Typed approval requests, session time in seconds. See [Upgrading to 3.0](/react-native-sdk/upgrading#upgrading-to-300-pre-release). |
| `@lazorkit/sdk-legacy` (web3.js v1) | 2.0.0 | `next` | v2 | `npm install @lazorkit/sdk-legacy@next`. Session time in seconds; the `/approval` subpath. |
| `@lazorkit/sdk-legacy` (web3.js v1) | 0.3.2 | `latest` | v1 | What a plain `npm install @lazorkit/sdk-legacy` installs. |
| `@lazorkit/sdk` (Solana Kit) | 1.0.0-rc.7 | `latest`, `next` | v2 | Release candidate. Session time in seconds. |

The two `sdk-legacy` lines are not wire-compatible: the same `userSeed` derives a
different wallet on each. The wallet packages depend on both: the 3.x / 2.x releases on
`@lazorkit/sdk-legacy` ^1.3.0 for v2 (a fresh install gets 1.4.0, which sends slots), 4.0 /
3.0 on ^2.0.0, and every release on 0.3.2 under the alias `lazorkit-sdk-v1` for v1 wallets.
`@lazorkit/sdk-legacy` 1.4.0 and `@lazorkit/sdk` 1.0.0-rc.6 and earlier send session
expiries as slots, which devnet's v2 refuses (3008).

Every release listed above names errors 3037 and 3038; the wallet packages report them as
`UnlistedSolOutflowError` / `UnlistedTokenOutflowError`.

## What works where today

| You use | Mainnet today | Devnet |
| ------- | ------------- | ------ |
| `@lazorkit/wallet` 3.x / adapter 2.x | Existing **v1** wallets keep working, through a relayer that sponsors v1 (`v1PaymasterConfig` / `v1ConfigPaymaster`). A user with no wallet cannot get one yet: new wallets are created on v2, which is not deployed on mainnet. | v2 wallets, plus v1 wallets made earlier on devnet. `createSession` on a v2 wallet is refused (3008). |
| `@lazorkit/wallet` 4.0 / adapter 3.0 (`next`) | As 3.x / 2.x. | v2 wallets, sessions included, plus v1 wallets. |
| `@lazorkit/sdk-legacy` 0.3.x | v1 | v1 (`4h3Xo…`) |
| `@lazorkit/sdk-legacy` 2.x, `@lazorkit/sdk` rc.7 | Nothing until v2 is deployed. | v2 |
| `@lazorkit/sdk-legacy` 1.x, `@lazorkit/sdk` rc.6 and earlier | Nothing. | v2, except creating a session (3008) |

When v2 is deployed on mainnet, this page is updated first.

## Which address is the user's wallet

Every LazorKit wallet has a **wallet PDA** (an internal account nothing can sign for)
and a **vault PDA** (where SOL and tokens live). Show the vault, fund the vault, and
use it as `fromPubkey`. The SDKs name them differently:

| SDK | Vault (show this, send funds here) | Wallet PDA (internal) |
| --- | ---------------------------------- | --------------------- |
| `@lazorkit/wallet`, `useWallet()` | `vaultPubkey`, `wallet.vaultPda` | `smartWalletPubkey`, `wallet.smartWallet` |
| `@lazorkit/wallet`, `LazorkitWalletAdapter` / Wallet Standard | `publicKey` | — |
| `@lazorkit/wallet-mobile-adapter`, `useWallet()` | `smartWalletPubkey` (= `vaultPubkey`), `wallet.smartWallet` | `walletPdaPubkey`, `wallet.walletPda` |
| `@lazorkit/sdk-legacy`, `@lazorkit/sdk` | `vaultPda` (`createWallet` also returns it as `depositAddress` in sdk-legacy) | `walletPda` |

<Callout type="error" title="Never send funds to the web SDK's smartWallet">
  On the web SDK, `smartWallet` / `smartWalletPubkey` is the **wallet PDA**. Funds sent
  there cannot be spent by anyone. On mobile the same name means the vault. When in
  doubt, use `vaultPubkey`, which means the vault on both.
</Callout>

Do not derive a user's vault yourself. The exported PDA helpers (`findVaultPda`,
`findWalletPda`, …) derive **v2** addresses, at the v2 **mainnet** id unless you pass
another program id, so they are wrong for a v1 wallet and for devnet. The SDKs store
the right vault for the wallet's protocol (`vaultPubkey` / `smartWalletPubkey`), and
backfill it on `connect` for wallets saved by older releases.

## Which cluster the SDK talks to

- **`@lazorkit/wallet` / `@lazorkit/wallet-mobile-adapter`** read the cluster from
  `rpcUrl`: a URL containing `mainnet`, `devnet` or `localhost`. Anything else is taken
  as **mainnet**. An RPC URL that does not name its cluster (your own proxy, most keyed
  provider URLs) needs the `cluster` prop: `cluster="devnet"`.
- **`@lazorkit/sdk-legacy`**: `new LazorKitClient(connection)` infers the program id the
  same way, but **throws** for a URL it cannot place. Pass the id:
  `new LazorKitClient(connection, PROGRAM_ID_DEVNET)`.
- **`@lazorkit/sdk`** (kit) always takes the program id: `new LazorKit(rpc, PROGRAM_ID_DEVNET)`.

```ts
import { Connection } from '@solana/web3.js';
import { LazorKitClient, PROGRAM_ID_DEVNET } from '@lazorkit/sdk-legacy';

const connection = new Connection('https://my-rpc.example.com', 'confirmed');
const client = new LazorKitClient(connection, PROGRAM_ID_DEVNET);
```

## Default endpoints

With no props, both UI SDKs use devnet:

| | Default |
| --- | --- |
| RPC | `https://api.devnet.solana.com` |
| Portal | `https://portal.lazor.sh` |
| Paymaster | `https://kora.devnet.lazorkit.com` |

LazorKit's devnet relayer for v2 is **`https://kora-devnet-production.up.railway.app`**.
Until `kora.devnet.lazorkit.com` moves to it, that name still reaches an earlier relayer,
so set the Railway URL yourself:
`paymasterConfig={{ paymasterUrl: 'https://kora-devnet-production.up.railway.app' }}` (web) or
`configPaymaster={{ paymasterUrl: 'https://kora-devnet-production.up.railway.app' }}` (mobile).

LazorKit's v2 relayer does not sponsor v1 transactions. An app with v1 users needs a
relayer that does, set as `v1PaymasterConfig` (web) or `v1ConfigPaymaster` (mobile).
See [Paymaster › Using a paymaster with the SDKs](/concepts/paymaster#using-a-paymaster-with-the-sdks).
